Executive handoff

Read this first

Decision-oriented summary

The most valuable outcome of this project is not one leaderboard number. It is a set of protocol, data, and training lessons that explain when the reported numbers are trustworthy—and when they are not.

Protocol dominates the headline

ModernBERT scored 86.88% in FPB cross-validation but 80.44% when FPB was excluded from training: a 6.44-point protocol gap.

v2-short is the best short/OOD v2

It beats v2-medium on nearly every external short-text view and reaches 69.52 macro-F1 on FiQA.

Stage 2 helps its own domain

Focal loss, rank 32, and F1-based selection improve internal medium text, but do not improve general short-text transfer.

Entity reasoning is unproven

Pair formatting does not yield entity-specific sentiment: all models remain around 43–44 macro-F1 on conflict rows.

There is no usable long model

The old Stage 3 truncated 52.8%; the replacement stopped before training when 78.2% truncation exposed malformed chunks.

Do not reuse the repository’s most flattering numbers without their protocol. The shipped v1 model trained on all FPB, so its latest 99.92% FPB score is memorization, not generalization. The Claude comparison also loads this production model on rows drawn from the same aggregate corpus, and the calibration result fits and evaluates on the production training set. Both need clean reruns.

Model choice today

Use narrowly

neoyipeng/ModernFinBERT-base
  • Full fine-tune on the complete aggregate corpus, all FPB, and 410 augmented rows.
  • Good as the existing simple-sentence production artifact.
  • No unbiased FPB estimate remains for these exact released weights.
  • Uses a one-hot/BCE training path while downstream treats outputs as mutually exclusive classes.
Best short/OOD evidence

v2-short

neoyipeng/ModernFinBERT-v2-short
  • Prefer for headlines, comments, tweets, and short financial passages.
  • Best external v2 results on FPB, FiQA, Twitter F1, and entity-conflict rows.
  • Stage 1 test: 76.95% accuracy / 77.11 macro-F1.
  • Entity input is optional formatting, not demonstrated reasoning.
Canonical medium release

v2-medium

neoyipeng/ModernFinBERT-v2-medium
  • Use only when the 4K-token medium-text distribution matches the task.
  • Internal medium: 69.71% accuracy / 58.86 macro-F1.
  • Regresses most external short-text tests versus v2-short.
  • Canonical v2 endpoint because Stage 3 was abandoned.
Terminology for future work: call v2 an entity-conditioned input experiment, not an entity-aware model. Reserve “entity-aware” for a model that passes controlled entity-removal, entity-swap, and multi-entity conflict tests.

How to read the rest

Evidence rules and repository state

Results live across committed prose, uncommitted analysis, ignored Kaggle output, logs, JSON, generated checkpoints, and hard-coded notebook summaries. The grades below prevent a plan or stale sentence from becoming a “finding.”

Saved run evidence

Structured JSON, training log, checkpoint state, or directly inspected data artifact. Highest local confidence, still subject to protocol quality.

Reported result

A metric retained in the paper, README, recipe notes, or notebook source, but no raw output remains. Preserve it with attribution and caveats.

Compromised inference

The computation may be real, but leakage, in-sample evaluation, test-driven checkpoint selection, or mismatched model identity prevents the intended claim.

No usable result

Designed but never run, failed before producing evidence, superseded, or broken. Keep the hypothesis, never the implied outcome.

Benchmark caveats that must travel with the numbers

  • v1 FPB is in-sample because the released production model trained on all FPB.
  • FiQA continuous scores are mapped with arbitrary −0.2 / +0.2 thresholds.
  • Twitter label IDs are remapped; possible training-source overlap is unaudited.
  • FinEntity uses its training split as evaluation and supplies oracle gold entities.
  • v1 receives entity: text; v2 receives a sentence pair. Input formatting is uncontrolled.
  • ModernBERT has no token-type embeddings; the pair contributes a separator, not segment IDs.
  • Sentence-majority ties depend on row order in the current implementation.
  • FPB all-agree is nested within 50%-agreement, so do not treat both as independent replications.

Curriculum track

What the v2 stages taught us

The surviving recipe is short-context Stage 1 followed by a carefully selected medium-context Stage 2. The curriculum teaches a general lesson: preserve a regression suite across prior stages, because improvement on the new distribution can conceal broad forgetting.

Stage 1 · saved log Shipped v2-short

Short-context foundation

34,597 train rows; max 512; ModernBERT + Unsloth LoRA r16/α32; three epochs; CE; learning rate 2e−4; effective batch 128. Validation rises .7313/.7320 → .7540/.7555 → .7598/.7610. Test: .7695 accuracy / .7711 macro-F1.

Old Stage 2 · saved log Superseded

Inverse-frequency weighting overcorrected

29,465 medium rows; max 4096; r16; weighted CE [4.18, 1.15, .53]; one end-of-epoch evaluation. Medium: .6314/.5428; short: .7473/.7480. NEG precision fell to .35 and the loss stayed relatively flat. Do not reuse this weighting recipe.

Old Stage 3 · saved log Negative result

Long-context training did not solve long context

8,000-row subsample; max 6144; r16; 125 steps. 52.8% of rows were still truncated. Long: .6264/.5422; medium: .6846/.5262; short: .7540/.7557; NEU recall .20. More context length did not repair malformed examples.

Stage 2 v3 · release + run note Shipped v2-medium

Focal loss and frequent macro-F1 selection worked internally

Fresh LoRA r32/α64 after merging Stage 1; focal γ=2; one epoch; ~500-row stratified interim validation; checkpoint every 50 steps by macro-F1; final full validation. Medium: .6971/.5886; short: .7561/.7580. Relative to old Stage 2: +6.57 accuracy and +4.58 F1 points on medium.

Stage 3 v3 · no train step Abandoned

Preprocessing assertion correctly stopped the run

Two operational failures came first: incompatible evaluation/save intervals, then an unbound Hugging Face secret after a Kaggle CLI push. The third attempt measured 78.2% truncation at 4096 and stopped. Stage 2 is the canonical endpoint; there is no v2-long release.

Stage-boundary invariants

  • Merge the previous adapter into the base before adding a fresh LoRA adapter.
  • Evaluate the new distribution and every earlier-stage regression set.
  • Select checkpoints with macro-F1, not loss alone, on imbalanced data.
  • Use a small stratified validation sample during 4K-token training, then one full final evaluation.
  • Persist the canonical v3 checkpoint/log locally; the current local Stage 2 checkpoint is the old r16 weighted-CE run.
Do not attribute the v3 gain to one knob. Focal loss, LoRA rank 32, fresh-adapter handling, frequent evaluation, and macro-F1 checkpoint selection changed together. A factorial or at least one-factor-at-a-time ablation is required for a causal claim.
The current notebooks are not exact run recipes. The retained Stage 1 log used one GPU, batch 64 × accumulation 2, and 813 optimizer steps; the current notebook uses batch 32 × 2 and comments roughly 1,623 steps. The current v3 medium notebook uses batch 16 × 2, implying roughly 921 one-GPU steps, while the recipe’s 461-step arithmetic is inherited from the old batch-64 baseline. Recover the missing v3 log or model revision before claiming exact reproducibility.

Negative result

Self-training with tweets hurt

Adding 3,217 high-confidence pseudo-labeled tweets moved FPB from .8256/.8052 to .8054/.7700 and aggregate test from .8083/.7633 to .7833/.7187. Validation fell .8354 → .8292, so the run stopped.

Lesson: a nearly one-hot teacher provides poor confidence ranking, and domain-mismatched pseudo-labels amplify bias rather than add supervision. The auxiliary pseudo-label “accuracy” check also omitted the Twitter label remap, and the summary used FPB to choose a model, so retain the negative direction—not every diagnostic statistic.

Regularization signal

LoRA beat the tested full fine-tune

LoRA exceeds full FT by +3.69 accuracy points without augmentation and +1.19 with it. This supports a small-data regularization interpretation, but only one full-FT recipe was tested.

The shipped v1 deliberately uses full FT, so this research conclusion and the production choice should not be conflated.

Where augmentation helped most

The paper’s class-F1 view moves NEG roughly 46.5 → 59.3 (+12.8), NEU 82.4 → 85.5 (+3.1), and POS 71.1 → 78.9 (+7.7). Error-targeted data helps the minority and confusing boundary classes most.

These values belong to the 246-row standard-prompt generation; do not relabel the class gains as VS-CoT evidence.

Cross-validation class behavior

In the reported 10-fold FPB run, class F1 is NEU .8984±.0082, POS .8081±.0217, and NEG .8556±.0355. NEG varies most across folds; neutral is easiest and most stable.

Because the held fold selected checkpoints, treat the exact means as optimistic.

Postmortem

Why entity conditioning did not become entity reasoning

The failure is explainable. The model rarely sees counterexamples where the target entity’s sentiment differs from the sentence label, often receives no specific entity at all, and uses a backbone with no token-type embeddings.

95.21% short-train entity label = sentence label

Only 1,656 training rows disagree, so the easiest strategy is to ignore the entity.

35.74% short-train specific entity coverage

64.26% are blank or generic sentinel inputs such as NONE/MARKET.

63.08% Stage 2 entity labels that are POS

The medium distribution teaches a strong positive prior; FinEntity is neutral-heavy.

.4428 best conflict macro-F1

v2-short is the best of three, but the absolute score does not demonstrate disambiguation.

Representation mismatch

  • ModernBERT does not emit token_type_ids; sentence-pair formatting supplies only separator tokens.
  • The natural v1 entity: text prefix may better match pretrained language patterns than a bare pair.
  • Gold entity names in FinEntity are oracle inputs, so production entity extraction is not tested.
  • Current annotations are frequently regex/dictionary entities with the sentence label copied over, not independent entity judgments.

Minimum proof for an entity-aware claim

  • Gold multi-entity sentences with opposing labels, including SEntFiN/FinEntity-style conflicts.
  • Prefix vs sentence-pair vs inline [ENT]…[/ENT] marker ablation on identical data.
  • Entity removal, shuffle, and swap counterfactuals; predictions must change in the expected direction.
  • Neutral-balanced sampling, far fewer generic/blank entities, and grouped document splits.
Suggested redesign: begin with marker-based spans on a conflict-rich gold set. Only consider a backbone with learned segment embeddings or custom segment features after proving that better supervision and simple markers are insufficient.

Raw augmentation duplicates

The raw augmentation CSVs contain 4,102 rows but only 1,164 unique normalized synthetic texts and 782 unique originals. They are cumulative snapshots, not independent shards.

Never concatenate the raw directory. Use the curated 410-row artifact or rebuild from a manifest with family IDs.

Long-data provenance break

scripts/chunk_sources.py actually tokenizes with ModernBERT and filters 500–3,072 tokens, despite comments about a 4.5 chars/token heuristic. The ignored long parquet has no token-count column and text is capped at exactly 32,000 characters.

Therefore the current script cannot explain the current long dataset. Trace the generating code, tokenizer revision, and hashes before rechunking.

Medium split leakage warning

Exact texts do not cross medium splits, but normalized first-200-character prefixes overlap 94 times train→validation, 97 times train→test, and 20 times validation→test. These are likely adjacent chunks from the same documents.

The builder prints leakage counts but does not fail. Future splits must group by source document before sampling chunks.

Annotation merge is not reconstructible

All 217 short annotation batches exist, but their entity coverage and label counts differ materially from the final parquet. A second NONE pass and 279 early-index manual overrides exist, yet no single merge driver explains the final 43,247 rows.

The medium builder also joins annotations by row order using .values, not by a stable key.

Processed data is locally present but not reproducibly built by the committed pipeline. Short entity annotation provenance and the exact long-dataset generator are missing; some surviving annotation scripts extract entities with regex/dictionaries and then copy the sentence label. Audit claims, licenses, split grouping, and exact hashes before publishing a dataset card.

Requires correction or rerun

These statements appear in current or historical repo material but are either invalid, stale, or too strong for the retained evidence.

“The model is already well calibrated.”

The saved run uses the production model on its 14,859-row training set, fits and evaluates with one fold, and gets 99.973% accuracy. Temperature T=1.00025 changes almost nothing and slightly worsens ECE (.0002421628 → .0002421686).

Calibration is unknown out of sample; rerun with grouped out-of-fold logits or a locked external set.

“ModernFinBERT fairly beat Claude by 10 points.”

The JSON says .8313/.7957 versus .7275/.7033 on 723 rows, but the script loads the production v1 trained on the aggregate corpus that contributed those rows. The benchmark gave Claude condensed rules, not the full skill.

Replace with

The saved comparison is contaminated for v1; rerun with a truly held-out checkpoint, frozen blind set, explicit model ID, and failure accounting.

“v1 reaches 99.92% on FPB.”

The exact released v1 was trained on all FPB. This is an in-sample identity check, not a benchmark. The honest held-out research generation is around 80–81% accuracy.

Replace with

Use the released v1 only with an external locked test or rebuild a model that never sees the FPB evaluation rows.

“v2 is entity-aware.”

Entity labels mostly equal sentence labels, 64% of short inputs have no specific entity, ModernBERT lacks segment embeddings, and conflict macro-F1 is only ~.44.

Replace with

v2 accepts entity-conditioned input; learned entity-specific behavior has not been demonstrated.

“v1 uses standard three-class cross-entropy.”

Many v1 notebooks pass one-hot float labels to Transformers, which auto-selects multi-label BCEWithLogitsLoss. Inference then applies argmax/softmax as though training were single-label CE. The local production config confirms multi-label mode.

Replace with

Document the historical BCE path; future training should use integer class IDs and explicit single-label configuration.

“10-fold CV is an unbiased final estimate.”

FPB CV selects the best epoch on each test fold and then reports that fold; production CV can also split paraphrase families across folds. Exact metrics are optimistic.

Replace with

Use nested validation inside each training fold and grouped family splits.

“The long data was token-aware chunked.”

The current script filters 500–3,072 tokenizer tokens, but the actual long parquet is character-capped and 78.2% truncates at 4K. The retained code and artifact do not share a provenance chain.

Replace with

The long dataset’s generator is unknown; hash and trace it before any new Stage 3 run.

“Notebook source proves the run happened.”

All 41 notebooks have null execution counts and zero output cells. NB17 variants also contain collapsed, syntactically invalid source. Several tables are hard-coded summaries.

Replace with

A run is supported only when its log, structured result, checkpoint state, or external artifact is retained.

“The +7.84 F1 gain proves Verbalized Sampling.”

The 246-example study that produced +7.84 aggregate-test F1 used standard prompting. A separate 410-row artifact uses VS-CoT and feeds later LoRA/full-FT experiments.

Replace with

Targeted augmentation helped; the incremental effect of VS-CoT over standard prompting remains untested.

“Architecture alone explains ModernBERT’s gain.”

The clean held-out gap is large, but checkpoint scale, pretraining data, tokenizer, and architecture move together. In same-protocol CV, the +1.09-point edge is not significant (p=.093).

Replace with

ModernBERT is directionally stronger under tested recipes; isolate pretraining and scale before making a causal architecture claim.

“The current notebook exactly reproduces the release.”

Stage 1 batch size and optimizer-step counts drift from the retained log, while the v3 medium recipe inherits 461-step arithmetic from the older weighted-CE run. Hugging Face revisions are unpinned.

Replace with

The current sources describe intended recipes; exact executed v3 lineage is incomplete until the missing log, config, and model revision are recovered.

Reproducibility and execution

Operational lessons worth keeping

T4-safe v2 training

  • Use explicit SDPA for long sequences; Flash Attention 2 is not reliable on T4 sm75.
  • Disable Unsloth fast generation and TorchDynamo for variable long lengths.
  • Use 8-bit AdamW and gradient checkpointing.
  • Keep evaluation/save intervals compatible when loading the best checkpoint.

Run provenance

  • A Kaggle CLI push does not preserve secret bindings.
  • Record commit, dirty diff, notebook hash, data hashes, model revision, package lock, seed, and hardware.
  • Save machine-readable metrics beside logs and checkpoint state.
  • Do not rely on generated checkpoint READMEs; they are boilerplate.

Current environment gaps

  • The local venv has packages but no usable Python launcher/activate script.
  • setup_environment.sh references obsolete Data.ipynb.
  • requirements.txt is broad and unpinned; Kaggle notebooks install ad hoc versions.
  • Critical data/checkpoints are ignored and not tied to a versioned manifest.

Protocol template for every future experiment

1

Freeze the question

State the one causal comparison, primary metric, dataset, split unit, and stop rule before training.

2

Lock provenance

Hash raw/processed data, record source licenses and families, freeze benchmark rows, model revision, environment, and prompt.

3

Separate selection from evaluation

Use train/validation for checkpointing and one untouched test. In CV, nest validation inside each training fold.

4

Retain evidence

Save per-example predictions, labels, logits, IDs, metrics, seed, config, and logs—not only notebook prose.

5

Run regression views

Evaluate prior-stage domains, class metrics, truncation, entity conflicts, and calibration before advancing.

6

Publish the nulls

Record failures and non-significant results with the same completeness as wins; never backfill a planned table as evidence.

What to do next—and the gate for continuing

The first priority is evidence integrity, not another large training run. Each item below has a decision gate so a weak intermediate result does not expand into an expensive experiment by momentum alone.

PriorityP0

Preserve the newest benchmark and create an experiment registry

Commit or deliberately archive the three-model notebook, log, JSON, exact model revisions, dataset revisions, and a manifest linking every headline metric to its artifact. Reconcile the two-model root JSON and update research.md with v2-short.

Gate: every number in README, paper, model cards, and this handoff resolves to one model identity, protocol, and retained artifact—or is explicitly graded “reported only.”
PriorityP0

Repair evaluation validity

Rerun calibration on grouped out-of-fold or locked external logits. Rerun the Claude comparison with a checkpoint that never saw the 723 rows, exact model ID, fixed prompt/rules, retries, and per-example outputs. Separate production-v1 from held-out-v1 cards.

Gate: no evaluation row or paraphrase family appears in training or checkpoint selection; calibration improves ECE/Brier/NLL on untouched data without material accuracy loss.
PriorityP1

Test entity learning, not entity formatting

Build a gold, conflict-rich, neutral-balanced set; compare prefix, sentence pair, and inline markers on identical splits; add entity remove/shuffle/swap counterfactuals. Audit whether annotations are regex proxies or independent judgments.

Gate: conflict macro-F1 improves materially across seeds and predictions respond correctly to entity swaps. If not, stop calling the task entity-aware and reconsider the backbone/objective.
PriorityP1

Resolve augmentation causality

Run a grouped, multi-seed factorial: no augmentation vs standard targeted paraphrase vs VS-CoT, with equal sample counts and independent validation/test. Keep original-paraphrase families together.

Gate: VS-CoT must beat standard prompting with confidence intervals on locked test data; otherwise retain the simpler conclusion that targeted augmentation helps.
PriorityP1

Rebuild long data before long training

Trace the exact current artifact first. Then rechunk original documents with the exact ModernBERT tokenizer, split oversized speaker turns/sections, cache token lengths, group by document, and reannotate only the regenerated chunks.

Gate: pre-truncation p50/p95/p99 are documented, <10% of training examples truncate at the chosen limit, and a dry-run memory profile succeeds. More GPU is not a substitute for passing this gate.
PriorityP2

Run clean architecture and adaptation studies

Multi-seed ModernBERT/BERT/DeBERTa comparisons need architecture-specific stable recipes and common data. DAPT → TAPT → supervised or contrastive training remains a high-upside hypothesis, not an observed gain; validate corpus licenses and dedup first.

Gate: pre-register primary OOD and held-out metrics; require consistent improvement across seeds and report significance. A one-class collapse is a recipe failure, not an architecture verdict.
PriorityP2

Finish the public documentation only after evidence cleanup

Regenerate the paper PDF; remove placeholder email/TBDs; correct trainable parameter and latency claims; add latest benchmark and Stage 3 outcome; create distinct v1-production, v1-research, v2-short, and v2-medium model cards.

Gate: automated link/claim checks pass and every public metric carries dataset, split, model revision, evidence grade, and contamination note where relevant.

Scope and method

The audit covered every project-authored document, script, notebook, structured result, log, artifact metadata file, paper source, skill document, and repository history relevant to experimental claims. It inspected ignored processed data and annotation batches through schema, aggregate statistics, sampled logic, and provenance relationships.

Opaque model weights, optimizer tensors, archives, images, and PDFs were inventoried and—where useful—checked through metadata or rendering rather than interpreted byte-for-byte. Third-party environment packages and internal Git object bytes were not treated as project knowledge. No secrets or local credential values are reproduced here.

Exact duplicate notebook families were counted but not reinterpreted as independent evidence: Kaggle pushes 13–16 mirror their archived v1 notebooks; Kaggle 17A mirrors archive 17A; the root and notebooks/02 benchmark notebooks share cell source; the older Kaggle push 02 is a two-model variant.
