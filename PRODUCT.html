One task: aspect-based financial sentiment

Every row is a piece of financial text and a target inside it. The model says whether the text is positive, negative or neutral about that target. When the caller has no target, the target is the whole text and the task is plain sentence sentiment. One model, one input format, one head. Two encoders ship: one small, one large. This document fixes what gets built, what the labels mean, and what counts as done.

Why one task, and why this one

The thesis

Claim under test

Sentiment without a target is guesswork. "Nokia beat Ericsson on margin" is good news for one company and bad news for the other. A sentence-level model has to pick one answer and is wrong about the other. That is not a hard example. In financial text it is the normal case, because a sentence about a market names the parties in it.

The target is part of the question

Ask "is this positive?" and the honest answer is "about what?". Bind the polarity to a named target and the answer becomes a fact you can check, store and join to other data.

Vanilla is the easy case of the same question

When the caller supplies no target, the target is the whole text. That is one code path, one head and one metric, not a second model. Plain sentence sentiment falls out of the aspect model for free.

This is what the earlier plan got wrong, then got wrong again. The first plan carried an aspect input and two other tasks. The scope change in DECISIONS_AIM.md deleted all three, because one of the three had a broken benchmark. The aspect work went out with it and it did not have that problem. This document puts the aspect back and keeps the narrowing, so the project has one task instead of three, and that one task is the useful one.

The thesis needs a correctness measure. Aspect macro-F1 remains the primary score. On each pair of targets whose gold labels differ, contrast-pair accuracy counts one only when both predictions are correct. The current share of different predictions stays as target sensitivity, which is diagnostic only. A random change can raise sensitivity and cannot raise contrast-pair accuracy reliably.

The matched control hides the target. Score the same checkpoint on the same rows after segment B is replaced with overall. The paired 95% interval for the contrast-pair gain must stay above zero. Document exact match, where every annotated target is correct, is the strict secondary result.

Exact input and output

Model contracts

Decided

Two fine-tuned encoders. Same task, same input format, same head, same evaluation harness. One small winner and one large winner may ship. Each winner is one unified model that handles target rows and overall rows. Specialist models are controls only.

The small tier runs first. It validates the full development-side pipeline: data, training, evaluation, calibration, cost, registry, report card and package. This first small winner is provisional because distillation needs the large winner. The frozen test split stays closed until both final candidates are locked.

Bulk scoring. Millions of rows, CPU or one small GPU, cost per million rows is the number that matters.

Two tiers, not three. DECISIONS_AIM.md entry A set the tier limits from the real gaps in the checkpoint roster: small is 70M or less, medium is 71M to 260M, large is 350M or more. No boundary sits on top of a checkpoint. Only small and large ship. The medium checkpoints still run, once each, so the size curve has points in the middle, but they are not candidates and they are not in the corrected test family. See the evaluation protocol.

Aspect extraction is out of scope. If nobody hands you a target, you get the null-target case, which is plain sentence sentiment. A separate extractor that finds the targets is a different model and a different project. Say this in the model card, in plain words, so nobody wires the model into a pipeline it cannot serve.

One format, both cases

The input format

Decided

The model reads a pair. Segment A is the text. Segment B is the target string. This is the standard strong format for aspect sentiment with an encoder, it needs no character offsets, and it works on every data source in the plan.

The two cases, in one format
CaseSegment ASegment BWhere it comes from
Aspect The sentence or headline The literal target string, copied from the text FiQA 2018, FinEntity
Null target The sentence or headline The fixed token overall Financial PhraseBank, and any caller with no target

Why overall and not an empty string. An empty segment B makes the two cases different shapes, and the model learns to read the shape instead of the target. A fixed literal keeps one shape. It also gives the null case a real embedding that training can move, which an empty segment does not.

Span markers, as one ablation

Where the source gives character offsets, the target span can be marked in the text instead, for example … shares in [T] Nokia [/T] rose …. FinEntity has offsets. FiQA has a snippet that usually matches a span. Financial PhraseBank has neither.

Markers are run once, as a head-to-head against the pair format, on the same rows and the same seeds. One variable. If markers win by a clear margin, the recipe changes and the rows without offsets fall back to the pair. If they do not, the pair format stands and the second code path never gets built.

Warning. Marker tokens change the tokenizer. New special tokens mean a resized embedding matrix, and that is not free on a small checkpoint. Price it in the smoke check before the head-to-head, not after.

Input length

Every source in this plan is sentence length or headline length. The token distribution is measured at the data build, and the maximum length is set from the 99th percentile of it, rounded up. It is a configuration number chosen from the data, the same way batch size is. It is not a claim and it is not on an experiment ladder.

If a later source brings paragraphs or filings, the number is re-measured and recorded as a new config with a new hash. That is a data change, not a research question.

What the three labels mean

Label codebook

Decided

Three classes. The label is the sentiment that the text expresses toward the target, from the point of view of an investor holding that target. It is not the mood of the writer and it is not whether the reader will enjoy the news.

positive

The text says something that is good for the target. Higher revenue, a won contract, a raised rating, a beaten estimate, a cut cost. The judgement is about the target, not about the sentence as a whole.

negative

The text says something that is bad for the target. Lower revenue, a lost contract, a cut rating, a missed estimate, a rise in a cost the target pays.

neutral

The text mentions the target and says nothing good or bad about it. Plain description, a factual count, a schedule, a name in a list. Neutral is a decision, not a shrug.

Rules that settle the hard rows

  • Same sentence, two targets, two labels. This is allowed and it is the point. Label each target on its own. Never average them into one sentence label.
  • The target is mentioned but the good news is somebody else's. Label the target neutral unless the text says the effect reaches it.
  • Costs cut both ways. A rise in the price of a thing is positive for the seller and negative for the buyer. Decide by which side the target is on.
  • Guidance counts. A statement about the future is labelled the same way as one about the past. Time direction is not part of this task any more.
  • No mixed class. A sentence that reports a number and then judges it goes in one bucket by the rules above. A fourth class lowers agreement and the label stops meaning one thing.

Warning. The borrowed labels were written to other codebooks. Financial PhraseBank asks its annotators for the view of an investor. FiQA gives a continuous score per aspect. FinEntity marks entity spans. None of them was written to the codebook above. The mapping from each source into these three classes is written down, published, and checked on a sample by a person. See benchmarks.

What the numbers are measured on

Benchmarks

Two of three open

Three human-labelled sources form three required evaluation cells. Financial PhraseBank tests the null-target variant. FiQA and FinEntity test the target-conditioned variant. There is no weighted composite that can hide a weak cell.

One winner per size tier. The highest macro-F1 is the leader in each benchmark. Another candidate ties that leader only when its gap is at most 0.01 macro-F1 and the Holm-adjusted 95% interval for their paired difference contains zero. A candidate is eligible only when it leads or ties on all three benchmarks. If none qualifies, that tier has no winner. Mean macro-F1 and then measured inference cost order several eligible candidates.

The multi-aspect rows stop being a problem and become the proof set. DECISIONS_AIM.md warns that a sentence carrying two aspects with opposite polarity cannot be scored by a sentence-level model. Under this scope those rows stay. Contrast-pair accuracy checks whether both target labels are correct. Target sensitivity only checks whether the predictions differ, so it stays diagnostic.

FinEntity was audited on 22 August 2026, and the gate passed. Run it again with finsent aspect-audit. The source publishes 979 documents. Eleven are exact repeats and eight label one target two ways, so 968 remain, and they carry 1,974 target rows. 542 documents name two or more distinct targets, and 119 of those give their targets different labels. Thirty hold a positive target and a negative one at the same time. Those 119 documents contribute 323 target rows, and they are the whole evidence for the aspect input.

Why this mattered. FiQA holds zero such sentences out of 1,111, so on FiQA alone the claim could not be measured at any model quality. FinEntity is what makes the headline number real. It is also ODC-BY, so it is the one human source here that the release may redistribute.

Warning. 323 rows across 119 documents measure the claim and do not fill a split. A test split cut from them alone would be too small. Pool the aspect rows with the null-target rows for training and report the proof-set measures over the frozen FinEntity split: contrast-pair accuracy, target sensitivity, document exact match and the paired gain over the target-hidden control.

Two smaller notes from the same audit. 65 of 2,104 spans carry offsets that miss their own value by one to five characters, always forward; every one is repaired by a search for the value nearest the recorded offset, and the repair count is printed rather than hidden. And the documents are short: a median of 34 words, and 623 of 979 are a single sentence. They are headlines and news snippets, not passages.

Warning. Financial PhraseBank is non-commercial and it cannot be redistributed. The repository publishes row identifiers and split assignments, never the text. That is settled in DECISIONS_AIM.md entry J and the code enforces it. It leaves the release with no evaluation set of its own. FinEntity is ODC-BY and closes part of that gap. A test set labelled for this codebook closes the rest. See the gap review, gap 3.

The splits

  • One test split, cut from the Financial PhraseBank 50%-agreement superset and frozen. Every row keeps the strongest agreement tier it reached, and the four published subsets are read back as breakdowns of that one split. The four subsets are nested, so four separate test splits are impossible and four overlapping ones leak.
  • The aspect sources are cut the same way, and the split key is the sentence, not the row. All targets of one sentence land in the same split. A sentence split across two splits leaks the sentence.
  • A near-duplicate group never straddles two splits. A paraphrase and its original never straddle two splits. The harness fails the build when either rule breaks.

What the encoder has to beat

The frontier baseline, pinned

gpt-5.6-sol, reasoning effort medium

Decided
Why it is here
It is what a practitioner calls instead of shipping an encoder. It is therefore the number that decides whether this project is worth building.
The pin, in full
One model, one version, one effort setting. Not a router. Not a fallback chain. Not "whatever was current". The effort setting is part of the pin, because it changes both the answers and the bill.
Prompts
Two, both published: zero-shot and few-shot. The few-shot examples come from the train split only, never from dev and never from test.
Cached
Every response is cached with its token counts and its date, and the cache is published. The benchmark then survives the model being retired.
How it is compared
Paired bootstrap by independent sentence or document group, with the cost per thousand rows on the same table.

Warning. It writes no labels. In the earlier plan a frontier model wrote the test key, and the headline was agreement with it. That is gone. Here it is a system scored against human labels like every other system, and it can lose.

Two lexicon numbers are missing and both are cheap. Read the word lists beside their abstention rate: Loughran-McDonald is silent on 65% of development rows and Henry on 66%, and every silent row is called neutral. Report the macro-F1 on the answered rows beside the full score. Then add one hybrid: feed the word-list counts into logistic regression. The sign rule throws the counts away, and the hybrid is the fair lexical baseline an encoder must beat.

What this project will not do

Non-goals

Decided

Each one of these was considered and dropped. A non-goal can be re-opened, and re-opening it needs a decision-log entry that says what changed.

Aspect extraction

The caller supplies the target. Finding the targets in free text is a different model, a different metric and a different project.

Forward-looking detection

Dropped in the scope change. Time direction is not a label here. Guidance is scored like any other statement.

Fact versus opinion

Dropped in the scope change, because the candidate benchmark split on time rather than on checkability.

Domain pretraining

No masked language modelling step. The bench answers which general encoder wins on this task. It does not answer which encoder is best for financial text, and the card must not claim it does.

A continuous score head

FiQA carries a real-valued score. It is mapped into the three classes and the mapping is published. A second head is a second code path for one source.

Multilingual coverage

English only. Every source in the plan is English. A multilingual claim needs multilingual test data that this project does not have.

Passage and filing input

Sentence and headline length only, set from the measured token distribution. Long input returns as a data change if a source brings it, not as a research claim.

A leaderboard

The release publishes numbers, splits and the code to reproduce them. Running a submission queue for other people is a service, not a model.

Who calls this, and why

Users and jobs

Assumed

The analyst with a news feed

Has a list of tickers and a stream of headlines. Wants one row per ticker per headline, not one row per headline. Calls the small model, in bulk, on CPU or one cheap GPU. Cares about cost per million rows and about the multi-target case, because a headline that names two companies is the one they cannot handle today.

The researcher with a panel

Needs a sentiment column that they can defend in a footnote. Wants the frozen split, the published numbers, the confidence intervals and the word-list floor beside them. Cares that the method is citable and that the numbers reproduce.

The engineer replacing an API call

Already calls a frontier model and is paying for it. Wants to know what accuracy they lose and what money they save. The macro-F1 against cost table is written for this person.

The bar, written before the runs

Definition of done

Numbers open

Seven conditions. All seven must hold. Each one is measured on the frozen test split, opened once, at the end. The thresholds go into settings.py from the measured baselines before the test split is opened, never after the table is read.

  1. Each tier has one valid unified winner. The model leads, or is within 0.01 macro-F1 of the leader with a Holm-adjusted 95% paired interval that contains zero, on Financial PhraseBank, FiQA and FinEntity. If no candidate clears all three cells, that tier has no winner.
  2. Both models beat the lexical floor with an interval. Macro-F1 above the best of the word lists, the hybrid and TF-IDF, with a paired bootstrap interval that does not cross zero.
  3. The aspect input earns its place. On target pairs with different gold labels, both predictions must be correct. The paired 95% interval for contrast-pair accuracy against the same checkpoint with segment B replaced by overall stays above zero. Target sensitivity is diagnostic only. Document exact match is reported.
  4. The null-target case does not regress. The aspect model scores at least as well on Financial PhraseBank as a model trained on those rows alone. One variable, three seeds. If the aspect rows hurt the vanilla case, the write-up says so and the release ships the number.
  5. The small model is worth its size. Its macro-F1 is within a stated distance of the large model, and its cost per thousand rows is at least an order of magnitude lower than gpt-5.6-sol at medium effort, counted on real token usage at recorded prices.
  6. Every headline number has a registry row. No row, no number. The row carries the hypothesis, the config hash, the split hash, the seed and the evidence grade.
  7. The card is honest about what was not done. No domain pretraining. No article-level grouping, because Financial PhraseBank ships no document identifier. A non-commercial source in the training data, named in the card itself.

The bar cannot move after the split is opened. Write the thresholds into the config, commit them, and hash the config. A bar that gets set after the numbers arrive is not a bar. This is the failure the previous project recorded, and it is the one that is easiest to repeat.

How a claim earns its grade

Evidence rules

Decided

Every number in the write-up carries a grade. The grade is a property of how the number was produced, not of how much anyone likes it. The registry refuses an unknown grade.

Supported

Measured in this repository, on a frozen split, through the harness, with a registry row and a confidence interval. Reproducible from the config hash.

Reported

Taken from somewhere else. A published paper, a model card, a transcribed word list. It carries its source and its protocol difference in the same row. It never becomes Supported by being repeated.

Compromised

Measured, but on a split that was fitted against, or with a rule that changed after the number was seen. Kept in the record and never used in a comparison.

State of the art

State of the art means the best published number on the same benchmark, on the same agreement subset. Financial PhraseBank is heavily published, so this is a real and checkable target. Three rules come with it and none is optional.

  1. Every quoted number carries its protocol difference in the same row. A number with no note is not publishable.
  2. Where the other system is downloadable, re-run it on this project's split instead of quoting it. A re-run is paired. A quote is not.
  3. A quoted number is graded Reported, never Supported.

Warning. Published Financial PhraseBank scores come from different subsets. 50%, 66%, 75% and all-agree are four different sets, and the all-agree subset is the easy one. A score on one is not comparable to a score on another. Record the subset in every row. This is the exact comparison that forced the last retraction.

The survey does not exist yet. No file holds the published scores, their subsets, their splits, their metrics or their citations. Until it does, the project has no target to aim at. Fill the table in Program design before the first GPU run.

What goes out, and in what state

Release checklist

Artefacts not built
  1. Two model repositories, weights and configs, permissively licensed, each with a version.
  2. A model card per model that names Financial PhraseBank and its non-commercial licence in the card itself, not behind a link.
  3. A dataset card for the split assignments, the manifest of hashes and the codebook.
  4. The aspect mapping from each source, published as data, with the sample a person checked.
  5. The gpt-5.6-sol response cache, with token counts, prices and dates.
  6. The augmentation prompts, the generator model name and its terms.
  7. One script a third party runs to reproduce a headline number end to end.
  8. The registry, complete, including the runs that failed.
  9. A limitations section that says the model is not investment advice, states the English-only scope, and states that no article-level grouping was possible.

Write the card template now, and fill it as the numbers arrive. An empty card with the right sections stops a rushed card at the end. None of these artefacts exists today.

The ways this goes wrong

Known traps

Live

The aspect input buys nothing

If the model ignores segment B, it is a sentence model with extra cost. Detect it with contrast-pair accuracy and its paired gain over the target-hidden control. Keep target sensitivity as a diagnostic, because different wrong answers do not prove that the target helped.

The three sources disagree about what a label means

Three codebooks mapped into one. Detect it by scoring a model trained on one source against the other two. A large drop is a mapping problem, not a domain problem.

The bench comes out flat

A tie needs both tests: a gap of at most 0.01 macro-F1 and a Holm-adjusted paired interval that contains zero. A loss in another benchmark is not hidden by an average. A tier has no winner when no candidate leads or ties on all three benchmarks. Mean macro-F1 and then inference cost order several eligible candidates. Do not add seeds to force a winner.

The test split is too small to tell

Compute the minimum detectable effect separately for Financial PhraseBank, FiQA and FinEntity. Use the same sentence or document grouping and Holm scope as selection. Do this before each tier runs. If a benchmark cannot resolve the 0.01 tie margin, grow the split, reduce the family or report that the winner rule is underpowered.

The development split gets used up

500 rows carry the baselines, the temperature scaling, the pooling choice, the error analysis and every augmentation arm. Cut a second development split, or publish the count of decisions that read the first one.

The generated rows cannot be released

If a hosted model writes the paraphrases, its terms may restrict what you do with the output. Choose the generator and read its terms before the first run, not after. Prefer an open-weight generator.
