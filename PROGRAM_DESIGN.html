The rules everything else follows from

Operating principles

Enforced in CI

Eight rules. Most of them are enforced by a test or a script, not by discipline. Anything that depends only on remembering will eventually be forgotten.

1

Freeze the test set before training anything

The borrowed test set for a task is adopted, re-split, reconstructed, hashed and committed before the first training run on that task. Its hash goes in the config, and so does the hash of its reconstructed passages. The eval harness refuses to score against a hash it does not recognise.

2

One variable per experiment

A run changes one thing. If two things change, the run tells you nothing about either. Multi-change runs are allowed only as a deliberate "does anything work at all" probe, and they are labelled as such in the registry.

3

Provenance travels with every row

Source, licence, label origin, codebook version. A row without provenance never enters a training set. A data-loading test enforces this.

4

Never look at the test set

Prompt tuning, labelling-function selection, label-model fitting, hyperparameter search, checkpoint selection, threshold picking. All of it happens on the development and validation sets. The test set is opened once per model, at the end.

5

Every claim names its refutation

Before writing a claim, say what result would have disproved it. If no such result exists, the sentence is an opinion and gets written as one.

6

Report the human ceiling next to the model

A macro-F1 of 0.84 means one thing if annotators agree 0.95 of the time and something else entirely if they agree 0.86 of the time. The ceiling is always in the table.

7

Negative results ship

A model that misses the bar is released with the miss stated. A method that did not help gets a paragraph in the write-up. The project is worth more as an honest record than as a set of wins.

8

If it is not in the registry, it did not happen

A number without a registry row cannot be quoted anywhere. Not in the README, not in the model card, not in conversation. This is the rule that the last project most needed and did not have.

Sequencing

Phases

One task per phase

Each phase takes one task from raw data to a released model. The first phase also builds the shared machinery, so it is the longest by a wide margin. Detailed scope for each is in Vertical slices.

Phase 1 — Forward-looking, and the harness

First

Goes first because it has the strongest borrowed benchmark of the three. Its sentences come from real 10-K filings, which are on EDGAR in full, so it is also the task most likely to get its passages back. That keeps the risk in the machinery rather than in the task. Everything reusable is built here: data schema, passage builder, passage reconstructor, weak-supervision pipeline, eval harness, run registry, baseline runners, model card template, CI.

It also runs the backbone bench once, for the whole project. Four encoder families at nine checkpoints, all at 512 tokens, which is the only length every candidate supports. That picks the encoder the other two phases inherit. It is a cheap experiment and it comes before the expensive one.

Then it runs the length ladder for the first time, which is the phase's real headline. Whatever 512 against 8,192 says on forward-looking sets the prior for the other two tasks, and it decides whether the long-context claim has legs at all.

Exit: one released model, one adopted and frozen benchmark with its match rate published, a length ladder, and a harness the next two phases use unchanged.

Phase 2 — Aspect-based sentiment

Second

Second because it adds one new thing to a proven pipeline, which is that the aspect goes into the input. FiQA 2018 supplies the benchmark, and it brings a target, an aspect taxonomy and a continuous score, so the score-to-class mapping gets decided and documented here.

It is also the phase where the long-context claim is dropped on purpose. FiQA is tweets and headlines. There is no document to recover, so this task ships sentence-level and its ladder measures cost, not accuracy. Better to plan that now than discover it at Gate 2.

Exit: released model, adopted benchmark, a documented mapping from the continuous source scores to the three classes, and a cost ladder rather than an accuracy ladder.

Phase 3 — Fact versus opinion

Third

Last because it is the only task with no matching public benchmark, so it carries the open decision described in the benchmark program. Either it becomes premise versus claim and adopts FinArg, or it keeps its current definition and ships a distillation claim with no accuracy number. Doing it last means the labelling pipeline is proven and priced before that call has to be made.

Exit: released model, the fork resolved in writing, a length ladder or a stated reason there is none, and a measured overlap with the forward-looking labels.

Phase 4 — Suite release

Last

The cross-model comparison table, the demo Space, and the write-up that tests the thesis. This is where the three models stop being three projects and become one claim.

Exit: public write-up with every number graded, and a demo anyone can paste text into.

Phases do not overlap. The temptation after Phase 1 is to start all three at once. Do not. The harness will need changes discovered in Phase 2, and changing it while three models are mid-training is how protocol drift starts.

The backbone bench runs once, in Phase 1. Phases 2 and 3 inherit the winner and do not re-run the nine candidates. The one thing that reopens it is a phase where the inherited backbone lands below the classical baseline, which would say the bench answered a question about forward-looking rather than a question about the encoder. If that happens, the bench is re-run on that task and both results are published side by side.

Every task runs its own ladder, and here is the rule for shortening it. The full ladder is three rungs at three seeds. Phases 2 and 3 may drop to the winning rung plus the 512 control, two rungs at three seeds, but only if Phase 1's ladder separated cleanly outside the noise band. If Phase 1 came out flat or mixed, the full ladder runs every time, because a flat result is exactly the case where one task's answer says nothing about another's. Whichever version ran is recorded in the model card.

Where labels come from

Data program

Decided

Three tracks, kept apart at every stage. They have different reliability, different licences and different failure modes. Merging them without a record is the mistake the last project made, and it made the results impossible to reconstruct.

Track A — Public labelled

Reproducible

Existing annotated datasets. Cheap, citable, and other people can check them. The catch is that none of them were labelled under this codebook, so their label meaning is close but not identical.

  • Used for training and validation.
  • Never used as the gold test set.
  • Each source gets a mapping note saying how its labels were translated.

Track B — Borrowed human

The referee

Published datasets whose labels were made by people, adopted whole and frozen. Nobody on this project annotates anything. No longer the headline, because the headline is now fidelity to the reference. This is the only track that can settle whether the student matches or exceeds the frontier model.

  • Test and development only. Never trained on.
  • Frozen and hashed before training starts.
  • Source, licence and published annotator agreement recorded per set.
  • The codebook is written to fit the borrowed labels, not the other way round.
  • Small, and somebody else's definitions. Both caveats travel with every number.

Track C — Weakly supervised

Scale, with doubt

Every passage labelled by k different models through one router, plus a few cheap heuristics, combined into one probabilistic label. This is where training volume comes from, and it inherits whatever the models get wrong together.

  • Training only, in its own split.
  • Deliberately not frontier models. Cheap is the point, because this track is bought at volume.
  • Label quality measured against a human development set, never against the test set.
  • Its contribution is proven by an ablation, never assumed.
  • Never the bar. The student is graded by the reference, which does not vote here.

Track R — The frontier reference

The headline

One pinned frontier model labels the test passages, and those labels are the answer key the headline is measured against. This track did not exist in the earlier plan, and adding it is what turns the project from an accuracy claim into a distillation claim.

The pin, in full: gpt-5.6-sol, reasoning effort medium, one shared prompt per task carrying the codebook definition, structured output. The effort setting is part of the pin. It is not a knob to tune later, because changing it changes both the answers and the bill.

Rules

  • One model, one version, one effort setting. Not a router, not a fallback chain, not "whatever was current". gpt-5.6-sol at medium effort, written into the config and the model card. A different effort setting is a different reference.
  • Verify the identifier resolves before buying anything. A single call at Gate 1, with the exact string, checking that the model exists, that medium effort is accepted, and that the returned metadata names the version you think you pinned. A typo here is discovered after the labelling spend otherwise.
  • It never votes in Track C. A model cannot both teach the student and grade it. This separation is the whole point of the track.
  • It touches the test split and nothing else. Not the training rows, not the development set, not the labelling-function prompts. Using it as a bigger cheaper ruler for Gate 4 tuning was considered and rejected. Tuning the teachers to match the reference would lift the headline while turning the weak-to-strong result into something engineered rather than found.
  • Every response is cached and published, including the reasoning token counts. Hosted models get deprecated. The cached labels are the durable artifact, so the benchmark still runs in two years when the model is gone.
  • Do not assume determinism. A reasoning model asked the same question twice can answer differently, so the cache is not an optimisation, it is the test set. Nothing re-queries the reference once the set is frozen.
  • It writes one answer key, at full passage length. The reference reads the whole passage, never a rung-trimmed copy of it. All three rungs of the student are scored against that single key. Running it once per rung would give the ladder three different answer keys, and two rungs both scoring 95% against two different keys is a tie that means nothing.
  • It is run three times over the key set, and the majority answer is the key. Its agreement with itself across those three runs is published. That is the reliability of the whole benchmark, and it is the ceiling on what any student can score against it. It is measured before the success bar is fixed, not after the training bill.
  • Its cost per 1,000 passages is the denominator of the cost ratio, because it is the thing a practitioner would otherwise pay for. Reasoning tokens are billed and are counted in, since medium effort is the configuration being compared against.

What it cannot do

  • It cannot be beaten on its own labels. It scores 100% there by construction. That number is never printed as a result.
  • It cannot tell you the student is correct. Only that the student copies it well. Fidelity and accuracy are different words and the documents use them differently on purpose.
  • It cannot be swapped mid-project. Changing the reference changes the answer key, which makes every earlier number incomparable. A new reference is a new experiment with a new registry row.
  • It cannot be assumed clean. It may have read the referee benchmarks during pretraining, which is why its score there carries the contamination caveat like everything else.

The circularity problem, and how splitting the roles fixes most of it

The old design had one failure baked in. The models that produced the training labels were also the baseline being compared against, so a student could not cleanly beat its teachers on answers the teachers wrote. Separating the three model roles removes most of that by construction, and it is worth being precise about which part is genuinely gone.

The teachers are no longer the bar. Training labels come from k cheap router models. The headline is agreement with a pinned frontier reference, which is a different model of a different tier and never votes in the ensemble. So the student is graded by something that did not teach it. That is the real fix.

What replaces the old circularity is a subtler one. The reference writes the answer key, so it scores 100% on its own test by definition. Agreement with it measures faithful copying, not correctness, and the write-up says so every time the number appears. Nothing about the headline shows whether the reference was right.

Which is what the referee benchmark is for. The borrowed human-labelled sets are the only place the student and the reference are both scored against labels neither wrote. That is where "matches or exceeds the frontier model" is settled, and it is the only place that sentence is permitted. Those sets are small, their label definitions are somebody else's, and the reference may have read them during pretraining. All three caveats travel with the number.

Two habits survive from the old plan. Every model is reported twice, once trained without Track C and once with it. And any comparison against a single teacher is labelled a distillation result wherever it appears, including in the model card. Contamination handling stays in the benchmark program.

Rules for adopting a borrowed set

The old version of this block was sampling rules, because the gold set was going to be sampled and annotated here. It is not. What is left is the discipline that has to be applied to somebody else's sample instead, and the first rule is the one that hurts.

  • You inherit their sample, including its biases. The distribution was chosen by other people for other reasons. Measure it, publish it, and stop describing it as the target distribution. Report per-source performance where the set carries a source field, and say when it does not.
  • Do not rebalance the classes. Same rule as before. Report the natural rate and handle imbalance in training, never in the test set.
  • Deduplicate before splitting, on full text, because boilerplate repeats across filings and the borrowed sets were not deduplicated against each other.
  • Group the split by document, call or company wherever the set carries such a field. Where it does not, say so in the model card rather than implying a grouped split that was never possible.
  • Rebuild the passage where a source corpus exists. The reconstructed passage is stored with the row, hashed with it, and its match method recorded. A row whose passage could not be rebuilt keeps its label and is scored at sentence length.
  • Publish the token-length distribution after reconstruction. If the long rungs have nothing long to work on, the ladder has nothing to measure, and that is a finding to report rather than a problem to hide.
  • Split once and freeze. Re-splitting after seeing results is the same as tuning on the test set, and it is easier to do accidentally with a borrowed set than with one you annotated yourself.

Long passages make the licence problem worse. A single sentence from a paid transcript is arguably a quotation. Two thousand tokens of it is not. Redistribution terms get checked against the passage length actually being published, not against the sentence. Where terms are unclear, publish document identifiers and character offsets instead of the text, and ship a script that rebuilds the passages from the source.

Where training labels come from

Weak supervision

Decided

Each passage goes to k different models through one router. Each model's answer is a labelling function. A label model learns how much to trust each one and returns a probabilistic label. The student trains on those. This is what makes a training set of tens of thousands of passages possible at all, and it brings its own failure modes.

1. RouteEach passage is sent to k models from different families, with the target span marked exactly as the student sees it. One prompt, one structured answer, abstention allowed.
↓
2. Add heuristicsTwo or three cheap rule-based labelling functions per task. Low coverage, high precision, and genuinely uncorrelated with the models.
↓
3. Build the label matrixOne row per passage, one column per labelling function, with abstentions marked rather than guessed.
↓
4. DiagnoseCoverage, overlap, conflict, and pairwise agreement per function, measured on the human development set.
↓
5. Fit the label modelSnorkel's label model against plain majority vote. Whichever wins on the borrowed human development set is the one used. The reference model is not consulted here, or anywhere outside the test split.
↓
6. Train the studentSoft labels, noise-aware loss. Low-confidence rows dropped by a threshold chosen on validation data.

Long passages make this the most expensive thing in the project

Labelling cost is roughly passage length times the number of models times the number of rows. Moving from 512 to 8,192 tokens multiplies the first term by up to sixteen, and k models multiply it again. A labelling run that would have been an afternoon's pocket change at sentence level is the largest single line in the budget at passage level.

Two consequences, both binding. Labels are bought per length rung, because a label produced from a 512-token window is not a valid label for an 8,192-token student and reusing it would quietly wreck the length ladder. And the pilot comes first at every rung, so the ladder's true cost is known before it is committed to.

Choosing the k models

  • Different families, not different sizes. Two versions of the same model fail in the same places and add almost nothing to the vote.
  • Five is the starting point. Enough for the label model to estimate accuracies, few enough to afford at 8,192 tokens.
  • Every model must handle the full passage length. A model that silently truncates is labelling a different task from the one the student learns.
  • Pin exact model identifiers per run. Router-hosted models get updated and deprecated, so an unpinned run is not reproducible.
  • Mix strong and cheap. A weaker model with a different bias can be more useful to the vote than a second strong one that agrees with the first.
  • Record cost per model per run. One expensive function is often removable at almost no quality cost, and you can only see that if you measured it.

The heuristic labelling functions

Cheap, transparent, and the only functions in the set that are genuinely independent of the models. They matter more than their accuracy suggests.

  • Forward-looking: future modals, expectation verbs, explicit horizon phrases, safe-harbour markers, applied to the target span. Abstain otherwise.
  • Fact versus opinion: attribution patterns, evaluative adjective lists, presence of a figure with a unit. Abstain otherwise.
  • Aspect sentiment: direction verbs near the aspect mention, negation handling. Low coverage, and useful where it fires.
  • Abstaining is normal. A function that answers on 15% of rows and is right almost every time is a good function.

The assumption most likely to be violated

A label model works by assuming its functions make mistakes for unrelated reasons. Large models trained on overlapping web text do not. When five of them are wrong they are often wrong in the same way and on the same rows, and the label model reads that agreement as confidence.

What is done about it. Pairwise conditional agreement is measured on the human development set and published. Model families are chosen to be as different as the router allows. Heuristic functions are included specifically because they break the correlation. And plain majority vote is always run alongside, because if the independence assumption is badly broken the learned model has no real advantage over counting, and pretending otherwise is the kind of unfalsifiable claim this project exists to avoid.

Budget discipline

  • Pilot on 500 rows first, at every length rung. Measure real cost per row per model, and measure label quality on the development set, before any full run.
  • Set a dollar ceiling per task and make the runner stop at it rather than warn.
  • Cache every response by hash of prompt plus model plus passage. A rerun after a bug fix should cost nothing for rows that did not change.
  • Drop functions that do not pay. If removing a model changes label quality by less than noise, remove it and note the saving.
  • Scale the row count to the gain. Plot student quality against training rows on validation data. Where the curve flattens, stop buying rows.
  • Consider labelling short and training long only as a measured experiment, never as a saving. If it works it is a real finding worth publishing. If it is assumed, it silently invalidates the ladder.

Where the benchmark comes from now

Benchmark program

Open item inside

There are two test sets per task now, and they answer different questions. The reference set is the same passages labelled by one pinned frontier model, and it carries the headline, which is fidelity. The referee set is borrowed whole from published datasets whose labels were made by people, and it is the only place a claim to match or exceed that frontier model can be settled. Nobody on this project annotates anything. This section names the borrowed sets, states what each one buys, and states what it costs.

The trade is real and it is not free. Hand annotation bought three things: labels that matched our own codebook, passages around every sentence, and an evidence-distance tag on every row. Borrowed labels buy none of them. The codebook now has to be rewritten to match somebody else's definitions, the passages have to be reconstructed from the source documents or given up, and evidence distance has to be inferred rather than recorded. Every claim that rested on those three things is downgraded or dropped below.

What this settles for free

  • The aspect vocabulary question is answered. FiQA ships its own taxonomy, so aspects come from the source rather than being invented.
  • The score mapping decision has a published reference point, because FiQA ships both the continuous score and a mapped class.
  • The annotator count question is closed. There is no second annotator because there is no first one.
  • Three months of annotation comes out of the schedule entirely.

What it costs

  • The forward-looking task becomes three-class. The binary codebook in Product is rewritten to match, or the labels cannot be used.
  • No passages ship with any of the three sets. Every row is a bare sentence.
  • No evidence-distance field exists, and it cannot be added without an annotator.
  • All three sets are public and indexed, so the frontier models in the ensemble may have seen them.

Rebuilding the passages

This is the step the whole long-context claim now depends on, and it is entirely automatable. Two of the three sets were cut from public corpora that can be searched. Each borrowed sentence gets matched back into its source document, and the passage around it gets rebuilt by the same passage builder the training data uses.

  • Match on exact normalised text first, then on a high-similarity fallback, and record which method matched each row. A fuzzy match is a weaker row and is marked as one.
  • Publish the match rate per set. It is the single number that says how much of the long-context claim survived.
  • Rows that fail to match keep their label and are scored at sentence length only. They are counted, not quietly dropped.
  • Reconstruction runs once and is hashed with the rest of the test set. Re-running it later against a changed corpus is a new experiment.
The bar, checked at Gate 2: if under 60% of a task's test rows recover a real passage, that task reports a sentence-level headline and its length ladder moves to agreement with the ensemble rather than accuracy against gold. Say which one happened, in the model card.

Evidence distance, without an annotator

The old plan had the annotator record where the deciding evidence sat. That field is gone. What replaces it is weaker, it is measured after the fact rather than before, and it must be labelled as such everywhere it appears.

  • The substitute is a context-sensitivity probe. Run the frontier reference three times on the bare sentence and three times on the full passage. The full-passage runs are already the answer key, so the probe only costs the bare-sentence half. A row counts as context sensitive when the flip rate between the two conditions is higher than the flip rate within them. Both rates are published.
  • The within-condition rate is not optional. Without it the probe counts the model disagreeing with itself as evidence that context mattered, and the long-evidence split is part noise. That noise then lands in the one result the whole length ladder is read on.
  • This is a model-derived split, not ground truth. It says the ensemble needed the context. It does not prove a person would have. The write-up says that in the same breath as the number, every time.
  • It cannot be recorded before the models exist, which was the whole point of the original field. So the split is computed once, frozen, hashed, and never recomputed after seeing a student's results.
  • If the sensitive bucket lands under 10% of recovered rows, report the long-context question as untestable on that task. That rule survives unchanged from the old plan and matters more now.
Evidence grade: results on this split are graded one level below results on the whole set, permanently. It is a plausible split, not a validated one.

The human ceiling

Every model card carries a ceiling next to the score. With borrowed labels the ceiling is borrowed too, and where the source never published one, the card says so instead of inventing a number.

  • Quote the source paper's agreement statistic where it exists, with the citation, and say plainly that it was measured by other people on their sample.
  • Where no agreement figure was published, the card reads "not published by the source". That is an honest gap. Filling it with a guess is worse than leaving it open.
  • Run a label-noise probe as a floor. Take the rows where every model in the ensemble agrees with each other and disagrees with the borrowed label, then read a sample by hand. That sample is small enough to be an afternoon, and it gives an upper bound on how noisy the borrowed labels are.
  • An LLM is still not an annotator. The probe finds candidate bad rows. It does not decide them, and its output never becomes the ceiling.

The reference set, built by machine

This is the set the headline is measured on, and building it needs no people at all. Sample passages from the target corpora, run the pinned frontier reference over them once, cache every response, freeze, hash. That is the whole procedure.

  • Size is a budget question, not a labour question. Nobody is reading these, so 5,000 passages per task is affordable where 1,000 hand labels were not. Bigger set, tighter intervals, and the long-evidence half stops being noise.
  • Sample from the real target distribution, stratified by document type and by passage length, with the proportions written down before sampling. This is the sampling discipline the old gold set was going to have, and it is now actually achievable.
  • Never trained on, never tuned against. Same rule as any test set. Its hash goes in the config and the harness refuses an unrecognised one.
  • One answer key, written at full passage length. The reference reads the whole passage, never a rung-trimmed copy. Every rung of the student is scored against that same key. The 512 student is then graded on evidence it was not allowed to see, and the gap that opens between it and the 8,192 student is the long-context result. Scoring each rung against its own key defines that gap away before the experiment starts.
  • Three repeats, and the majority answer is the key. A reasoning model asked the same question twice can answer differently, so one pass is not a stable key. Publish the reference's self-agreement across the three passes. It caps what any student can score, so if it lands under the success bar the bar was never reachable and that is known before anything is trained.
  • Publish the cached labels with the model identifier and the prompt. That is what makes the number reproducible after the model is retired.
The one number that is not a result: the reference's agreement with its own labels. It is 100%, it is meaningless, and it never appears in a table.

Splitting the borrowed referee sets

The frozen test set

Borrowed, re-split, hashed
  • FLS. Keep the published 1,000-row test split unchanged, so published numbers stay comparable.
  • FiQA. The official 150-row test split is too small to read a result from. Pool all 1,213 rows and cut 500 for test, grouped by target company. Score the official 150 as well, and report both.
  • FinArg. One 969-row split ships. Cut 600 for test, grouped by call.

The development set

200 per task
  • Carved from the borrowed rows that are not in test, at split time, and hashed separately.
  • Still what the labelling functions, prompts and thresholds get tuned against.
  • Still never a headline number, because it has been tuned against.
  • Grouped by document or company, so a tuned-on row cannot reappear in test wearing a different sentence.

A borrowed row used anywhere else poisons the benchmark. These datasets ship train splits, and those splits are tempting free training data. Any row that lands in Track B is banned from Track A and Track C by identifier, and the harness fails the build on an overlap. Two of the sets ship no document identifier, so grouped splitting cannot be fully verified on them. Near-duplicate checking on full text is the fallback, and the model card states that document-level grouping is unverifiable for those sets.

Contamination, and where it now bites. All three borrowed sets are on Hugging Face and have been for years. The headline is safe from this, because it is measured on freshly sampled passages the reference labels itself. What is exposed is the referee comparison, which is the one claim that says the student matches or exceeds the frontier model. A reference that memorised those rows scores higher there than it should, and the student's win looks smaller than it is. Two partial defences. Report the reference's score on the referee set next to its score on fresh unlabelled passages from the same corpora, and flag any large gap. And note that the reconstructed-passage version of each row is not the published form, so a memorised sentence label is less directly reusable there.

Open decision, and it changes the third product. No public dataset matches the fact-versus-opinion codebook. FinArg's premise-versus-claim labels are close in spirit but not the same rule, and its own examples show it: a sentence beginning "I think" is labelled a premise there, and would be opinion under our codebook. Two ways out. Adopt premise versus claim as the real task and rename the model, which keeps a human benchmark and a defensible accuracy claim. Or keep fact versus opinion and ship it with a distillation claim only, measured as agreement with the ensemble plus cost and latency, with no accuracy number at all. The recommendation is the first, because a published human benchmark is the thing this whole programme is built around. Decide before Phase 3 opens.

The thing you have to beat

Baseline program

Same harness as the models

A weak baseline makes a weak result look strong. The LLM baseline gets the same care as the model, or the headline claim is worthless.

BaselineWhy it is runRules
Majority class The floor. If a model is near this, something is broken. Computed from the training split, applied to test.
TF-IDF + logistic regression Tells you how much of the task is surface vocabulary. Forward-looking in particular may be largely lexical, and that is worth knowing and saying. Hyperparameters tuned on validation only.
The same encoder at 512 tokens The internal control for the long-context claim. Same data, same recipe, same seeds, shorter input. Every statement about what long context bought is a difference against this run. Identical in every respect except max length. Run at three seeds, like the long rungs.
Every other benched backbone Shows whether the chosen encoder was actually the best one, and what the runners-up cost. Ettin's four sizes also give a parameters-versus-score curve, which says whether the medium tier is already at the ceiling. All nine candidates at 512, three seeds, one shared label set. Scored on validation for the pick, and the winner alone is scored on the borrowed test set. No delta is ever reported between two candidates at different maximum lengths.
The pinned frontier reference gpt-5.6-sol at medium reasoning effort. It writes the test labels, so the headline metric is how often the student agrees with it. Its agreement with its own labels is 100% by construction and is never reported as a result. On the referee benchmark it is scored like any other system, and that is the one place it can be beaten. One prompt, the codebook definition, structured output, every response cached and published so the benchmark outlives the model. Its cost per 1,000 passages, reasoning tokens included, is the denominator of the cost ratio.
The routed teacher ensemble The actual teacher, and deliberately not frontier. All k cheap labelling functions combined by the same label model used for training. Its agreement with the reference is the number the student is trying to exceed, because exceeding it is the weak-to-strong result. Identical pipeline to the training-label run, including the pinned model list. Its full cost is measured, and reported as the one-off price of building the student rather than as a running cost.
Each single routed model Shows which teachers carried the ensemble, and how far a single cheap model gets on its own. Reported per model, over the full passage. Always labelled as a distillation comparison, since the student trained on these labels.
Zero-shot single model Shows what the prompt engineering was worth, which is itself a useful published result. The codebook definition goes in the prompt, and nothing else.
Plain majority vote The dumb version of the ensemble. If it matches the label model, the label model is not earning its complexity. Same labelling functions, no learned weights, ties broken by a fixed documented rule.
Existing public finance encoder Shows the delta over what is already downloadable, where a comparable model exists. Label spaces must be mapped explicitly, and the mapping published. Where no clean mapping exists, do not force one.

Fairness rules for the LLM baselines

  • The prompt gets a real effort budget. Several iterations against the development set, not one attempt.
  • The full codebook definition goes in the prompt. Do not handicap the models by underspecifying the task.
  • Parsing failures count as abstentions in the label matrix and as errors in the baseline table. Both rates are reported.
  • Exact model identifiers are pinned and recorded, since a router can silently serve a newer version.
  • The LLM reads the same passage the model reads. Not a trimmed version, not the sentence. If the encoder ships at 8,192 tokens, the LLM gets those 8,192 tokens. This is the reference in its baseline role, competing on the referee benchmark at the shipped length. It is not the answer-key role, which is always run at full passage length and produces one key for every rung. The config names which of the two jobs a run is doing, because the numbers are not interchangeable.
  • Where the source passage is longer than the encoder's limit, both get the same trimmed passage, and the trimming is done once by the same code.
  • Run it three times and report the spread, because even at temperature 0 the output can move.

Measuring the cost claim

  • Count actual input and output tokens for the whole test set. Do not estimate. Long passages make input tokens the dominant term, and that is the heart of the cost story.
  • Price at published list rates, with the date recorded, since prices change.
  • For the encoder, report throughput at its shipped length and the per-second cost of the GPU it ran on, so the comparison is like for like. Report CPU inference too.
  • Report cost per 1,000 passages for both, and the ratio, at every rung of the ladder. A reader choosing 2,048 over 8,192 needs to see what that saves.
  • Report the labelling spend and the training spend separately, per length rung. Labelling dominates, and it is the number a reader planning their own run most needs.
  • Report the setup cost prominently. The student needed a labelling run, a training run and 1,200 human labels. The ensemble needed none of that. Quote the break-even volume where the student becomes cheaper overall, because that is the number a practitioner actually needs.

What every run must record

Experiment protocol

Registry-backed

One row per run in a registry file, written by the training script and not by hand. A run without a row cannot be quoted. This is the direct fix for the previous project's reproducibility gap.

Registry row fields

FieldMeaning
run_idStable identifier, generated from the config hash and the start time.
taskOne of fls, absa, factop.
hypothesisOne sentence, written before the run, saying what this run is testing.
variableThe single thing changed relative to the named parent run.
parent_run_idThe run this one is a variation of. Makes the experiment tree readable.
config_hashHash of the full resolved config, including data selection.
data_revisionDataset version and hash for every split used.
gold_hashHash of the frozen test set. Mismatch aborts the run.
max_lengthWhich rung of the length ladder this run is. A first-class field, because it is the project's main variable.
truncationMeasured trimming statistics at this length, written by the gate before training starts. A run whose gate failed has no training metrics and says why.
control_run_idThe 512-token run this one is compared against. Empty on the control itself.
seedRandom seed. Three seeds per reported configuration.
envLibrary versions, GPU type, CUDA version. Says plainly whether this rung ran on free or rented hardware.
metrics_valValidation metrics, per epoch.
metrics_testTest metrics. Empty until the run is promoted to a final evaluation.
artifact_pathWhere the checkpoint actually is.
evidence_gradeSupported, reported, compromised, or not run.
notesAnything that went wrong. Especially anything that went wrong.

Run discipline

  • Write the hypothesis first. If you cannot say what the run tests before starting it, you are not running an experiment, you are hoping.
  • Three seeds before any comparison. A one-seed difference of a point or two is noise. Report mean and spread.
  • Checkpoint selection on validation macro-F1, evaluated often enough to catch the peak. The previous project found frequent selection helped.
  • Test evaluation is a separate deliberate step, run once per candidate model, and it writes to the registry.

When a run is compromised

  • Grade it compromised in the registry with the reason. Do not delete it.
  • Any number from it is unusable, including numbers that look good.
  • If the compromise came from a code path, add a test that would have caught it before rerunning.
  • A preprocessing assertion that stops a run is a success, not a nuisance. The last project had one fire correctly and it saved a bad result from shipping.

Permission to continue

Decision gates

Can fail

Each gate is a real stop. Failing one means fixing the cause, not carrying on and hoping the next phase covers it. A gate that never fails is decoration.

Gate1

The benchmarks are admissible, and the reference is pinned

Two things pass together. The referee set's labels were made by people, and the source says so. Its licence permits the use and the redistribution actually planned. Its class definitions are written into our codebook verbatim, with every place they differ from the original intent recorded. Its published annotator agreement is quoted, or its absence is stated. No row overlaps any training source.

And the frontier reference is verified. gpt-5.6-sol at medium effort resolves on a live call, returns the version metadata expected, is confirmed absent from the router's model list, and its response cache is writing. Its terms of service permit using its outputs this way, which is a licence question as real as the dataset one and is easier to get wrong.

If it fails: do not adopt the set. A benchmark whose labels mean something slightly different from the codebook produces a headline that means something slightly different from what it says, and no reader can detect the gap. This is now the cheapest failure in the programme and the most expensive one to skip.
Gate2

Data is clean, and the passages came back

No near-duplicates across splits, checked on full passages. Every row has provenance. Every target span resolves inside its passage. Licence confirmed for every source that will be redistributed, at the passage length being published. Class rates and token-length distribution recorded. And the reconstruction bar is met: at least 60% of the test rows recovered a real passage from the source corpus, with the match rate and the match method published per row.

If it fails on leakage: no training run starts. Leakage found later invalidates everything downstream of it, and long passages make leakage easier, not harder. If it fails on reconstruction: the task drops to a sentence-level headline and its length ladder is reported as agreement with the ensemble rather than accuracy. That is a documented outcome, not a blocker, but it must be named in the model card rather than glossed.
Gate3

The length budget holds

At the rung about to be trained: trimming affects under 5% of rows, nothing within two sentences of a target is lost, and the configuration actually fits the available hardware for a full run.

If it fails: the run does not start. Fix passage assembly, or drop to a lower rung and record why. This is the gate the previous project did not have, and its absence is the whole reason the earlier long-context result was uninterpretable.
Gate4

Weak labels are worth buying

On the borrowed human development set, and only that set, at the length rung about to be labelled, the label model beats both plain majority vote and the best single labelling function. Coverage, conflict, pairwise agreement and measured cost per row are all recorded.

If it fails: do not buy labels at volume yet. Either the functions are too correlated to combine usefully, in which case use majority vote and say so, or the prompt needs work. At passage length this is the one gate whose failure costs real money rather than time, so it runs on a 500-row pilot before every full run.
Gate5

Model beats the classical baseline

The fine-tuned encoder clearly beats TF-IDF plus logistic regression on validation data.

If it fails: stop and diagnose. Either the task is lexically trivial, which is a publishable finding on its own, or the training pipeline is broken. Do not tune hyperparameters until you know which.
Gate6

Model meets the success bar

The bar is fidelity, cost and latency, all measured once on the frozen reference-labelled test set. Agreement with the pinned frontier reference at or above 95% of passages. Cost ratio against that same reference at least 50×. Latency within budget at the shipped length. The full length ladder is reported, including the rungs that lost.

Three more numbers are required but do not gate. The teacher ensemble's own agreement with the reference, so the weak-to-strong comparison is readable. The student and the reference scored side by side on the referee benchmark, which is the only place a claim to match or exceed the frontier model is allowed. And the confusion matrix of student against reference, so a reader sees where they part company rather than only how often.

If it fails: the model still ships, with the miss in the model card and an honest section in the write-up about why. Failing this gate does not block the next phase. Hiding it does. A ladder that comes out flat is a reported result, not a failure. A student that lands below its own teachers is also a reported result, and an informative one.
Gate7

Release is reproducible

A clean checkout plus one command reproduces the published table from the released checkpoint and the released dataset.

If it fails: nothing is published. A number that cannot be reproduced from the public artifacts is exactly the problem this whole programme exists to avoid.

The programme-level stop rule. If Phase 1 fails Gate 1, 2 or 4 twice, stop and reconsider the task definition before spending time on Phases 2 and 3. Three models built on a shaky label definition is three times the wasted effort.

And the long-context stop rule. If Gate 3 fails twice at 8,192 on the same task, ship the highest rung that passes and say in the model card that 8,192 was attempted and abandoned, with the reason. Do not keep retrying it, and do not describe the shipped model as long-context if it is not.

Who does what

Roles and working style

Assumed

Only you can do this

  • Deciding what a result means. Especially deciding when a result is not good enough to claim.
  • Licence and redistribution calls. An agent can read the terms. It cannot accept the liability.
  • Accepting a borrowed benchmark at Gate 1. Adopting someone else's labels means adopting their definitions and their mistakes. That is a judgement call, not a check.
  • The fact-versus-opinion fork. Renaming the third task or dropping its accuracy claim changes the product, so it is not an agent's decision.
  • Reading the label-noise probe sample. Perhaps an afternoon, and the only hand-labelling left in the whole programme.
This list used to start with annotation. That was months of work and it is gone. What is left is a handful of decisions and one afternoon of reading.

Good agent work

  • Harness, scripts, tests, CI. Well-specified engineering with a clear definition of done.
  • Dataset surveys. Finding what exists and what its terms are, with links, for you to verify.
  • Baseline runners and the cost measurement plumbing.
  • The routed labelling runs, once the prompt and the model list are fixed.
  • Drafting model cards and the write-up, from registry numbers rather than from memory.

Rule for agent work. An agent may write any code and may draft any text. An agent may not decide that a number is good enough to publish, and may not put a number anywhere without its registry row and evidence grade. Any pull request that adds a number without a registry reference gets rejected.

What will probably go wrong

Risk register

Live
RiskWhy it is likelyResponse
The borrowed labels mean something slightly different Every existing dataset was labelled for someone else's purpose, under someone else's rules, by people who are not available to ask. The gap is usually small and always invisible in the score. The codebook is rewritten to match the borrowed definitions rather than the other way round, and every known difference is listed in the model card. Gate 1 refuses a set whose definitions cannot be written down cleanly. The forward-looking task becomes three-class because of this rule.
Reconstruction fails and the long-context claim dies All three borrowed sets ship bare sentences. The long-context claim now depends on matching those sentences back into source documents that may be missing, revised, or paywalled. Measure the match rate first, at Gate 2, before any training run. Below 60% the task ships a sentence-level headline and says so. FiQA has no document to recover at all, so that task is planned as sentence-level from the start rather than discovering it late.
The reference has memorised the referee benchmark All three borrowed sets are public and have sat on Hugging Face for years. The one claim that needs the referee is "the student matches or exceeds the frontier model", and a reference that memorised the answers inflates exactly that comparison. Score the reference on the referee set and on fresh unlabelled passages from the same corpora, and publish both. A large gap is reported as suspected contamination, and the match-or-exceed claim is downgraded accordingly. The reconstructed-passage form of each row is also not the published form, which helps a little.
Fact versus opinion has no matching public benchmark It is the least studied of the three in a finance setting, and the nearest public set labels premise versus claim, which is a different question. An open decision, stated in the benchmark program. Either rename the task to premise versus claim and keep a human benchmark, or keep the current definition and ship a distillation claim with no accuracy number. Recommendation is the rename. Phase 3 runs last, so there is time to decide.
The borrowed test sets are small FiQA ships 150 test rows and FinArg ships 969 in one split. Confidence intervals on a 150-row three-class test are wide enough to swallow most differences worth reporting. Re-split FiQA and FinArg into larger test sets, grouped by company or call. Report the official split as well so published comparisons stay possible. Where an interval is too wide to separate two rungs, say the ladder was inconclusive rather than picking the higher number.
The student cannot reach 95% agreement It learns from cheap teachers and is graded against a frontier reference. If the teachers disagree with the reference in a consistent way, the student inherits that gap and no amount of training closes it. Measure the ceiling first, and it has two parts. The reference's agreement with itself across the three key passes is a hard cap on what anything can score. The teacher ensemble's agreement with the reference is an estimate of how far the student can get. Both are known before training starts, and the bar is fixed once both are on the table. If either lands under 95%, move the bar and say why. Do not discover this after the training bill.
The student beats its teachers and nobody believes it Weak-to-strong sounds like a bug. A student trained on noisy cheap labels scoring higher than the ensemble that produced them is the expected behaviour of a label model that denoises, but it reads as leakage. Make it falsifiable rather than asserting it. Publish the teacher ensemble's agreement, each single teacher's agreement, plain majority vote, and the student, all on the same frozen set. Gate 4 already proves the label model beats its best member, so the mechanism is documented before the result appears.
The frontier reference is deprecated Hosted models get retired, renamed and silently updated. The answer key would then be unreproducible, which is the exact failure this programme exists to avoid. The cached reference responses are the artifact, not the model. They are frozen, hashed and published with the test set, so the benchmark runs unchanged after the model is gone. Re-labelling with a newer reference is a new experiment with a new registry row, never a refresh.
Labelling spend runs away k models across tens of thousands of 8,192-token passages, re-bought at every rung of the ladder and every time a prompt changes. This is now the largest cost in the project and the easiest one to lose control of. A 500-row pilot before every full run, at every rung. A hard dollar ceiling in the runner. Response caching keyed by prompt, model and passage. A learning curve that says when to stop buying rows.
Router models change underneath you Hosted models get updated, deprecated and silently reassigned. A rerun months later is not the same experiment, and long-context support in particular varies between versions. Pin exact model identifiers per run and record them. Cache all responses. Treat a model list change as a new experiment with a new registry row, not a rerun of the old one.
The backbone bench comes out flat Nine checkpoints on one task with a 200-example development set is not much resolution. Modern encoders of similar size often land within a point of each other on a single classification task. That is a publishable result, and it is a cheap one. If the top few sit inside each other's confidence interval, the CPU tie-break picks the model and the card says the pick was made on latency rather than on accuracy. Do not run more seeds hunting for a separation that is not there.
NeoBERT will not export or will not take LoRA It ships custom modelling code loaded through trust_remote_code, so the ONNX path and the LoRA target-module names are both untested here. Find out in the bench, not at release. Pin the revision so the code cannot move underneath a rerun. If it will not export, it stays in the accuracy table and is not offered as the CPU model, stated plainly. If it will not take LoRA, run it as a full fine-tune at 512 only and label that row as the different recipe it is.
The CPU export work eats a week and returns nothing ONNX conversion and quantisation fail in ways that have nothing to do with the research question, and NeoBERT's custom modelling code is the likeliest to fight back. It is easy to sink days into a number that decides nothing. CPU inference is optional. Try the plain PyTorch path first, timebox anything harder, and drop it the moment it resists. The cheap-inference claim stands on the GPU and router numbers, which are measured anyway. Where no CPU number was taken, the cards say nothing about CPU speed rather than guessing.
Long context does not help Small training sets and more tokens to attend to is a real recipe for no gain, or for a loss. The 512 control runs on every task, so the answer is measurable rather than arguable. A flat ladder ships as the short model, with the ladder published. That is a result the field is short of.
Long passages leak across splits Boilerplate repeats across filings. At 8,192 tokens two rows from different documents can share most of their text. Near-duplicate checks run on full passages, not targets, and they fail the build. Grouped splitting by document stays in place on top of that.
The test set has no long-evidence examples The borrowed sets were sampled by other people for sentence-level tasks, so they lean towards self-contained sentences. There may be nothing for the long rungs to win on. The evidence-distance field is gone, so the substitute is the context-sensitivity probe: rows where the ensemble's answer changes once the passage is added. If that bucket lands under 10% of recovered rows, say the question was untestable on that task rather than reading a result out of noise. The probe is model-derived, so its results are graded one level below everything else.
Licences block the dataset release Financial text is commercially valuable and often restricted, and borrowed datasets carry their original terms with them. Two of the three adopted sets have no licence declared on the hub at all. Confirm terms at Gate 1, before adoption, not after training. Reconstructed passages come from EDGAR where possible, which is public domain in the US. Where terms are unclear, release row identifiers and document offsets rather than the text itself, and link to the original set rather than mirroring it.
Scope creep back into non-goals Aspect extraction, whole-document modelling and hierarchical chunk aggregation all feel like natural next steps once the input is already long. The non-goals list in Product, plus the rule that adding one back needs a decision-log entry. 8,192 is the ceiling and the caller cuts documents into passages.
The thesis turns out to be wrong Three labels may simply not cover as much of finance NLP as claimed. That is a finding. The write-up has a section for what the three labels miss, and it gets written whatever the answer is.

The output that outlives the models

Write-up plan

Phase 4

Written from the registry, not from memory. Every number traceable to a run row. The structure is fixed now so the results cannot quietly reshape the argument later.

Sections

  1. The thesis, stated as a claim that could be wrong.
  2. The three tasks, with the full codebooks.
  3. The protocol, before any results. Deliberately first, so the reader judges the method before seeing the numbers.
  4. Data, including the tracks and their reliability.
  5. Results, one table per task, every baseline, every interval, the human ceiling in the same table.
  6. Does length help, the full ladder on all three tasks, split by evidence distance, with the 512 control alongside. This is the paper's actual contribution and it gets its own section whichever way it comes out.
  7. Cost and latency, per rung, with the training cost and any rented GPU time stated too.
  8. What did not work, at similar length to what did.
  9. Thesis test, taking real finance NLP tasks and showing coverage and gaps.
  10. Limitations and quarantined claims.

Rules for the text

  • No number without an evidence grade.
  • No comparison across different protocols, ever, even with a caveat.
  • Confidence intervals in every results table, not just the text.
  • The word "state of the art" does not appear.
  • Where an earlier plan changed, say so and say why. The move from 512 tokens to 8,192 is the largest such change and it gets its own paragraph, including what the previous project's long-context failure did and did not show.
  • "Long context helps" is never written without the control run, the interval, and the evidence-distance split next to it.
  • The thesis section reports what the three labels miss, in the same detail as what they cover.
