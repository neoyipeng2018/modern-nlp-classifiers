The rules the work obeys

Operating principles

Decided
  1. One variable per experiment. Two changes at once produce a number that explains nothing. If two things must move together, that is one arm and the write-up says so.
  2. No row, no number. Every result has a registry row that carries the hypothesis, the config hash, the split hash, the seed, the cost and the evidence grade. The registry is append-only and it keeps the runs that failed.
  3. Nothing is fitted on the rows it is scored against. The harness refuses a split whose hash does not match the config, and it refuses an evaluation split holding a non-human label.
  4. The bar is written before the numbers. Thresholds go into settings.py and get hashed. A bar set after the table is read is not a bar.
  5. Stop when the curve flattens. Run the largest expected gain first. A method that does not move the number is a finding, and the next one starts.
  6. A tie is a result. "The backbone did not matter at this data scale, so pick on cost" is useful and honest. Do not add seeds hunting for a separation the correction removed.

The leak that already happened once. In the previous project both augmented sets were built from validation errors, and that same validation set then picked the checkpoint. Every validation estimate was optimistic and the work had to be retracted. Three rules stop it here, and the code enforces the third: errors are collected on a training-side fold, a paraphrase and its original always land in the same split, and CI fails the build when a family straddles two splits.

Order of work

Phases

Sequential

Four phases. Each ends with a number that is published whether or not it is flattering. The phase boundary is a gate, and a gate can send the work back.

Phase 1 · The floor

Done

Skeleton, config hashing, the append-only registry, the frozen splits, and the lexical baselines. No GPU, no spend, no open decision. It ends with a real published number that every later result is read against.

Delivered: majority 0.2546, Loughran-McDonald 0.4426, Henry 0.5896, TF-IDF plus logistic regression 0.7385, all macro-F1 on the 500-row development split.

Phase 2 · The aspect task

Next

Load the aspect sources, write the mapping into the three classes, build the pair input, cut the aspect splits on the sentence key, and add the aspect baselines. It ends with the multi-target count, which is the size of the effect this project claims.

Phase 3 · The bench

Priced, not run

Grouped five-fold cross-validation over the human rows that are not in the test split, across the small and the large tier. Holm correction over the family. It ends with one small checkpoint and one large checkpoint, or with a declared tie and a pick made on cost.

Phase 4 · The lifts, then the release

Not started

Data boost, distillation, intermediate fine-tune, self-training, noise cleaning. In that order, stopping when the curve flattens. Then the test split is opened once, the cards are written, and the weights go out.

Where every row comes from

The data tracks

Decided

Four tracks. Every row carries its label_source, and the harness refuses an evaluation split that holds anything other than a human label. That one rule is what keeps a machine-written key out of the headline.

The tracks, and what each is allowed to touch
Tracklabel_sourceWhere it comes fromMay appear in
A · HumanhumanFinancial PhraseBank, FiQA 2018, FinEntityTrain, dev, test
B · WeakweakLabel rules, a routed model, self-training on unlabelled newsTrain only
C · DistilleddistilledThe large model's probabilities over unlabelled or weakly-labelled textTrain only

What the data build already found

  • Financial PhraseBank ships 4,846 lines in its widest file. Eight sentences appear more than once. Two carry contradicting labels between their copies and are dropped, because letting the last read win would pick a label by file ordering. 4,836 usable sentences remain.
  • 59 rows fall into a near-duplicate cluster with another row. A cluster never straddles two splits.
  • The four published agreement subsets are nested, so one test split is cut from the 50%-agree superset and every row keeps the strongest tier it reached. The four subsets are read back as breakdowns of that one frozen split.
  • Financial PhraseBank ships no document identifier, so grouped folds have no article key. Two keys stand in: the paraphrase family, and the near-duplicate cluster. The card must say that article-level grouping was not possible.

Warning. The self-training corpus has no name. "Financial news sentences" is a direction, not a data set. Name it, check its licence, hash it, and check that it does not overlap the test split. Nothing downstream of self-training can start until it exists.

Turning three sources into one task

Making aspect rows

Mapping not written

Each source describes its targets differently. The build turns all three into the same row shape: a text, a target string, and one of three labels. The mapping is code, it is published, and a person checks a sample of it.

Financial PhraseBank → null-target rows

The target is the literal overall. The label is unchanged. One row per sentence. These rows teach the model what the null case means.

FiQA 2018 → aspect rows

Each row carries a target snippet and a continuous score in the range minus one to one. The target string is the snippet. The score maps into the three classes by two thresholds, and the thresholds are fitted on the train split only, never on the split they are scored against. Publish the thresholds and the class counts they produce.

A sentence carrying two aspects with opposite polarity produces two rows with different labels. Under the old sentence-level scope those rows were unscorable and the build counted them for removal. Here they are kept and they are the point.

FinEntity → aspect rows, with offsets

Each annotated entity span becomes one row. The target string is the span text and the offsets are kept, so this is the source the span-marker ablation runs on. It is the only permissively licensed human source in the plan, and it carries the most multi-target sentences.

Warning. Three codebooks are being mapped into one. None of the three sources was labelled to the codebook in the product spec. Check the mapping on 100 rows per source, by hand, and publish the disagreement rate. A high rate means the sources cannot be pooled and the write-up reports them separately.

The split key is the sentence, not the row. All targets of one sentence go to the same split. Split them and the model sees the sentence in training and is scored on it in test. The harness fails the build when a sentence straddles two splits, the same way it already does for near-duplicate clusters and paraphrase families.

Labels without annotators

Weak supervision

Three pieces missing

Five methods. They run in the order below and the work stops when the curve flattens. Weak labels never enter an evaluation split.

The five methods, in run order
#MethodWhat it buysCost
1Distillation from the large modelThe small model learns the large model's judgement. Required by the two-tier release, so it runs whatever the result.GPU only
2Intermediate task fine-tuneWarm up on the 50%-agree subset, then train on the all-agree subset. Cheapest of the five and it needs no new data.GPU only
3Self-training on unlabelled newsExtra training rows for no labelling money.GPU, plus a corpus that does not yet exist
4Label rules and a routed modelWeak labels at scale. The heuristic rules are also scored as baselines in their own right, which is free.API spend, capped
5Label noise cleaningThe borrowed labels are known to be imperfect.GPU only

Warning. Fix the position of label noise cleaning before the first ablation starts. It changes the training set under everything above it. It runs first or it runs last. Cleaning in the middle invalidates every ablation that ran before it. This is still open.

Three pieces that do not exist yet

  1. The corpus. Self-training needs a named, licensed, hashed set of unlabelled financial news sentences. Not EDGAR: filing prose does not match this task.
  2. The label model. Several weak sources produce several labels for one row. Nothing says how they combine. Majority vote and a learned label model give different answers. Choose one and write it down.
  3. The budget. The routed model costs money per row. Set a cap in dollars before the first call. This gates all API spend and it is still open.

How weak labels get checked

Score every weak source against the human labels on a held-out human slice, and publish the table. A weak source is only useful if you know how wrong it is. Then run one sweep over the mix: 0, 1, 3 and 10 weak rows for each human row. That ratio is the main knob in weak supervision and no experiment in the plans varies it.

Track D

Data boost

Designed, not run

Augmentation is a first-class data track with its own label source, its own split rules and its own provenance. With domain pretraining out and two of three tasks gone, it is the largest single lever left in the project.

The factorial. One variable, three arms, three seeds, equal sample counts.
ArmWhat it doesPrior evidence
1 · No augmentationThe control—
2 · Error-targeted paraphraseParaphrase the rows the model gets wrong, keep the label+2.92 accuracy, +7.84 macro-F1 in learnings.html, on this exact task and data
3 · Verbalized SamplingOne call returns several distinct variants with stated probabilitiesNone. Its gain over plain paraphrase is untested

Verbalized Sampling must beat plain paraphrase with a confidence interval, or the write-up keeps the simpler conclusion that targeted augmentation helps. Every model is reported twice, with Track D and without it, on the same frozen rows.

The aspect case makes one new augmentation possible

Counterfactual target pairs. Take a sentence with one target and a clear label, swap the target for another entity in the same sentence, and label the new row from the codebook. This teaches the model that segment B changes the answer. It was dropped with the aspect input and it comes back with it. Run it as a fourth arm, after the three above settle.

Warning. Choose the generator model and read its terms before the first run. Nothing in the plans says which model writes the paraphrases. That choice decides whether the generated rows and the weights trained on them can be released at all. Prefer an open-weight generator. Record its name and its terms in settings.py.

Warning. Check every generated row against the test split. A paraphrase that lands near a test row is a leak by another route. Run the near-duplicate check between the generated rows and the frozen split, and fail the build on a hit.

Which encoder, and how it is chosen

Picking the encoder

Decided

Two tiers ship, so two tiers are benched. Grouped five-fold cross-validation over the human rows that are not in the test split. Every human row is used for training and for picking, at different times. The frozen test split is never opened for the bench.

The roster. Tier limits follow the real gaps in the checkpoints, so no boundary sits on top of one.
TierLimitCandidatesIn the corrected family?
Small70M or lessEttin 17M, Ettin 32M, DeBERTa-v3-small 44M, Ettin 68MYes
Medium71M to 260MEttin 150M, ModernBERT-base 150M, DeBERTa-v3-base 184M, NeoBERT 250MNo. One run each, as points on the size curve
Large350M or moreModernBERT-large 395M, Ettin 400M, Ettin 1BYes

Why the medium tier leaves the family. Nothing ships from it, and every extra candidate in a Holm family costs power on a 1,000-row split. Cutting the family from eleven to seven lets the same rows detect a smaller gap. The medium checkpoints still run once each, so Ettin still prints a clean accuracy-against-size curve across six sizes. They are reported and they are not tested.

Two recipe choices, settled before the bench locks

  • Head and pooling. CLS against mean pooling. Encoders differ, so this is decided first, one config line and one run per candidate.
  • Pair against markers. The input-format head-to-head from the product spec, run on the sources that carry offsets.

Cost. Seven candidates, three seeds, five folds is 105 short runs, plus four medium reference runs. Price it at the smoke check before committing. Nothing counts the total run budget across the whole project, and that number should exist before phase 3.

What the project aims at

The published-number survey

Empty

State of the art means the best published number on the same benchmark and the same agreement subset. This table is where those numbers go. It used to be specified as configs/published.yaml. There is no config directory any more, so the survey lives here, in the plan of record, and it is filled by hand before the first GPU run.

Ten to twenty rows, filled before the bench. Every row carries its subset.
SystemScoreMetricSubsetSplit and foldsCitationDownloadable?
Empty. Nobody has run the survey. Until it is filled the project has no target to aim at.

Three rules come with every row, and none is optional.

  • Record the agreement subset. 50%, 66%, 75% and all-agree are four different sets, and all-agree is the easy one. A score on one is not comparable to a score on another.
  • Record the protocol difference in the same row. A number with no note is not publishable.
  • Grade a quoted number Reported, never Supported. Where the other system is downloadable, re-run it on this project's split instead of quoting it. A re-run is paired. A quote is not.

Warning. This project cuts its own split, so nothing in this table joins to this project's numbers. The published papers use their own splits, and many use ten-fold cross-validation over a subset. Two numbers on two different splits are not comparable. Re-runs fix half of it, and the plans already schedule them. The other half needs one run of each shipped model on the protocol the papers use, joined to this table. Do that, or drop the phrase "state of the art" from the release and say the project publishes a new benchmark instead. Both are honest. Only one of them is free.

How the numbers are produced

Evaluation protocol

Decided

The metrics

  • Primary: macro-F1 over the three classes, computed per row, where a row is one text and one target. The majority baseline scores 0.62 accuracy and 0.25 macro-F1 on this data, and that gap is why accuracy is secondary.
  • Reported three ways: all rows, null-target rows only, aspect rows only. A model that wins overall by winning only the easy half is not winning.
  • Multi-target discrimination. On sentences with two or more targets carrying different gold labels, the share where the model predicts different labels for those targets. This is the number that tests the thesis.
  • By agreement tier. Macro-F1 on the whole Financial PhraseBank split, then broken down by 50%, 66%, 75% and all-agree. It shows how the score tracks annotator agreement, which is the closest thing this task has to a human ceiling.
  • Calibration. Expected calibration error, with one temperature scalar fitted on the development split. The report card has the field and nothing fills it today.
  • Cost. Latency at batch size 1, throughput at batch size 32, peak memory, parameter count, on one stated machine. Printed on the same table as macro-F1.

The statistics

  • Paired bootstrap on the same rows, 10,000 resamples, alpha 0.05.
  • Every candidate is tested against the incumbent leader. The family is Holm-adjusted, and the rule goes into settings.py before the bench runs, not after the table is read.
  • Three seeds per configuration, and the seed ensemble is reported too. The runs already exist, so the ensemble costs nothing.

Compute the minimum detectable effect before the bench. Nobody has computed the smallest gap that a 1,000-row test split can detect after the correction. Without it a flat bench has two readings: the backbones are equal, or the split is too small to tell. Those are different findings and only one of them is publishable. Use the class balance and the bootstrap that are already in src/finsent/eval/.

Where the work can stop

Gates

All can fail

Seven gates. Each one has a condition that can be false. A gate that cannot fail is decoration, and the previous project had several.

The gates, in order
#GateFails whenThen what
1Benchmark admissibleA source's licence forbids the use, or its labels cannot be mapped into the codebook at an acceptable disagreement rateDrop the source and say so. Do not quietly re-map it
2Splits soundA sentence, a near-duplicate cluster or a paraphrase family straddles two splitsCI fails the build. Fix the key, re-cut, re-hash
3Aspect worth havingThe multi-target count is too small to measure, or the model gives one answer per sentence anywayThe aspect input is not earning its cost. Report it and reconsider the scope
4Bench poweredThe minimum detectable effect is larger than the gaps in the published literatureGrow the split, or cut the family, or state up front that the bench measures a tie
5Encoder beats the floorThe best candidate does not clear the lexical hybrid and TF-IDF with an intervalStop. An encoder that cannot beat a word list is not a release
6Success bar metAny of the six conditions in the definition of done is false on the frozen splitPublish the failure. Do not re-open the split to look for a better cut
7Release cleanA licence question is open, or an artefact on the release checklist is missingHold the upload. Licence calls are the owner's, not an agent's

What gets published, and in what order

The write-up

Outline only

The write-up leads with the result, not with the method. If the bench comes out flat, it leads with the tie.

  1. The claim. Aspect-based sentiment with a target input, where plain sentence sentiment is the null-target case, and the multi-target number that tests it.
  2. The floor. Word lists, their abstention rates, the hybrid and TF-IDF. Every reader checks Loughran-McDonald first.
  3. The bench. Accuracy against size across six Ettin sizes on one recipe, with the corrected family marked and the reference runs marked separately.
  4. The lifts. Each ablation with one variable, reported whether or not it worked. Track D reported twice, with and without.
  5. The comparison. gpt-5.6-sol on the same rows, paired, with the cost per thousand rows beside it. This is the table the release exists to print.
  6. What was not done. No domain pretraining. No article-level grouping. No multilingual claim. The non-commercial source in the training data.

Publish the failures. The registry keeps the runs that did not work, and the write-up names the methods that did not move the number. A method that failed here is useful to the next person, and hiding it is how the field stays stuck.
